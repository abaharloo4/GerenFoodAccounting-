# Guidelines - سیستم حسابداری و تطبیق صندوق کافه

## ۱. اصل راهنما برای ایجنت‌های AI

قبل از هر تغییر یا افزودن قابلیت، ابتدا `agents.md` را بخوانید. این فایل مرجع اصلی نحوه‌ی کار روی این پروژه است.

## ۲. زبان و جهت رابط کاربری

- تمام متن‌های رابط کاربری فارسی هستند، بدون استثنا
- جهت‌گیری کل UI باید RTL باشد (`dir="rtl"` روی سطح root و استفاده از CSS منطقی مثل `margin-inline-start` به‌جای `margin-left`)
- اعداد در UI باید با جداکننده‌ی هزارگان نمایش داده شوند (مثلاً ۱,۰۰۰,۰۰۰)؛ تصمیم بگیرید ارقام فارسی (۰-۹) یا لاتین نمایش داده شوند و در کل برنامه یکدست اعمال کنید
- فونت باید از یک فونت فارسی خوانا (مثل Vazirmatn) استفاده کند

## ۳. تاریخ و زمان

- تمام تاریخ‌های ذخیره‌شده در دیتابیس به فرمت ISO میلادی (برای مرتب‌سازی و محاسبات صحیح) ذخیره شوند، اما همیشه در UI به شمسی تبدیل و نمایش داده شوند
- تبدیل فقط در یک لایه‌ی مشخص (`utils/jalaali.ts`) انجام شود، نه پراکنده در کامپوننت‌ها
- ساعت سیستم همیشه بر مبنای `Asia/Tehran` محاسبه شود، مستقل از تنظیمات ساعت ویندوز کاربر در صورت امکان

## ۴. منطق محاسباتی

- فرمول تسویه هرگز نباید مستقیم در کامپوننت React پیاده‌سازی شود؛ همیشه از `calculation.service.ts` استفاده شود
- هر تغییر در فرمول باید تست واحد (unit test) مرتبط داشته باشد، حداقل برای مثال عددی تأییدشده در PRD
- اعداد مالی هرگز با نوع `float` جمع/تفریق مستقیم در UI نمایش داده نشوند؛ محاسبات نهایی حتماً در لایه‌ی service انجام و گرد شود

## ۵. دیتابیس و migrations

- هر تغییر در schema باید یک فایل migration جدا داشته باشد، هرگز schema.sql مستقیم دستکاری نشود بعد از اولین اجرا در محیط واقعی
- هیچ داده‌ای هرگز حذف فیزیکی (`DELETE`) نشود؛ به‌جای آن از soft-delete یا وضعیت `status` استفاده شود (طبق نیاز نگهداری تاریخچه تا ۶ ماه-۱ سال)
- هر عملیات create/update/delete روی جداول اصلی باید یک رکورد متناظر در `audit_log` ثبت کند

## ۶. امنیت

- رمز عبور هرگز plain-text ذخیره نشود؛ همیشه bcrypt با salt مناسب
- renderer process هرگز دسترسی مستقیم به Node APIs یا فایل‌سیستم نداشته باشد (`contextIsolation: true`, `nodeIntegration: false`)
- فایل دیتابیس SQLite در مسیر داده‌ی کاربر (`app.getPath('userData')`) ذخیره شود، نه در پوشه‌ی نصب برنامه

## ۷. دسترسی‌ها (Authorization)

- هر IPC handler باید نقش کاربر درخواست‌دهنده را validate کند، حتی اگر UI دکمه را مخفی کرده باشد
- حسابدار فقط به shift هایی که `accountant_id` آن‌ها برابر خودش است دسترسی خواندن/نوشتن دارد، مگر اینکه shift توسط مدیر قفل شده باشد
- مدیر به همه چیز دسترسی کامل دارد بدون استثنا

## ۸. کیفیت کد

- TypeScript strict mode فعال باشد
- کامپوننت‌های React باید کوچک و تک‌مسئولیتی باشند؛ فرم‌های چندتایی (اعتباری/کسری/اضاف) از یک کامپوننت مشترک `RepeatableEntryList` استفاده کنند تا تکرار کد نداشته باشیم
- هیچ مقدار hardcoded مالی یا فرمولی در کامپوننت‌ها نباشد

## ۹. مستندسازی مستمر

طبق روال همیشگی این پروژه‌ها، بعد از هر تغییر مهم:
- `roadmap.md` بروزرسانی شود (وضعیت فاز)
- `debug_log.md` در صورت رفع باگ یا تصمیم فنی مهم بروزرسانی شود
- `agents.md` در صورت تغییر قوانین کاری بروزرسانی شود
